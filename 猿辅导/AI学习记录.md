#### Motiff UI 生成工作流（motiff-ui-generation skill）

基于 Motiff MCP 的设计稿转代码方案，核心思路是**图为主、数据为辅、分阶段控制上下文**。

##### 依赖的两个 MCP

| MCP | 返回内容 | 用途 |
|-----|---------|------|
| `motiff-official` | 节点截图（PNG） | 布局参考 |
| `motiff` | 节点 JSON（颜色/字号/间距等精确数值） | 样式值提取 |

HTML 通过内置 CLI 脚本（`motiff-prefetch`）单独拉取，**只用来提取图片/SVG 的素材 URL**，不参考其结构（Motiff 导出的 HTML 结构杂乱，不可信）。

##### 三种数据的分工

| 数据 | 来源 | 用途 |
|------|------|------|
| 截图 PNG | motiff-official MCP | 布局结构参考，AI 看图推断真实视觉意图 |
| HTML | motiff-prefetch CLI | 只取素材 URL（图片地址、SVG 路径） |
| JSON | motiff MCP | 精确样式数值（颜色、字号、间距、圆角等） |

##### 五阶段工作流

```
Phase 1 → Phase 2 → [人工确认] → Phase 3 → Phase 4(循环) → [人工确认] → Phase 5(可选)
  分析      预获取     等待确认     生成页面    迭代修改         等待确认      拆分组件
```

**Phase 1 — 截图分析 & 规划**
- 只调用截图 MCP，不拿 JSON（防止过早耗上下文）
- AI 看图识别页面区域划分、布局方案、状态设计
- 产出 `planning-doc.md`，列出子组件清单（供 Phase 2 建映射用）

**Phase 2 — 批量预获取**
- 根据 Phase 1 规划，用浅层 getNode 找到每个子组件的真实节点 ID
- CLI 脚本并发批量下载所有节点的截图 + HTML 到 `.motiff/` 目录
- MCP 批量下载所有节点的 JSON
- 产出 `node-mapping.md`（区域名 → 节点 ID 的映射表）
- **此阶段结束后强制暂停，等用户确认再继续**

**为什么 Phase 2 后要人工确认：**
Phase 1 和 Phase 2 都是 AI 推断（看图分区域、猜节点映射），两步都可能有偏差。Phase 3 生成代码成本高，让用户在进入生成前确认节点映射是否正确、规划方向是否对，比生成完再返工便宜得多。

**Phase 3 — 生成完整页面**
- **只读根节点的三个文件**（截图 + HTML + JSON），不读子组件数据
- 一次性生成完整 `index.tsx` + 样式文件，重复元素用 render 函数/map 内联处理，不过早拆组件
- 子组件数据留给 Phase 4 按需消费（保护上下文窗口）

**Phase 4 — 迭代修改**
- 用户指出哪里不对 → 查 `node-mapping.md` 找对应子组件 → 只读那个子组件的数据 → 精准修改
- 循环直到满意

**Phase 5（可选）— 拆分组件**
- 满意后，按 Phase 1 规划把大文件拆分成独立组件文件

##### 关键设计原则

1. **截图是布局唯一参考**，JSON/HTML 只用来取精确值，不从数据结构推断布局
2. **Phase 2 一次性预获取所有数据**，后续不再调 MCP，避免重复消耗上下文
3. **Phase 3 只读根节点**，子组件数据按需读取，精准控制每轮的上下文用量
4. **先完整后拆分**，Phase 3 生成全量代码，Phase 5 再决定组件边界

##### 使用方式

```
请帮我还原这个页面：

- Project ID: abc123def456
- 主页面 Node ID: 145:5556
- 目标路径: src/app/react/my-feature/
- 技术栈: react-module-scss

变体节点（只列出有变化的部分）：
- 空状态: 145:5560
- 加载中: 145:5562
```

注意：只开 `motiff-official` 和 `motiff` 这两个 MCP，其他 MCP（如 Confluence）会大量占用上下文。
